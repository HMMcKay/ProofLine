Documentation / Evidence protocol

ProofLine protocol version 2

Bind exact received bytes to an inspectable history.

Signed protocol objects use deterministic canonical JSON, ES256 signatures and SHA-256. The exported bundle is designed to be checked without trusting the web presentation.

Identity and session authority

strongbox
Server-verified Android key attestation reports StrongBox-backed key material.
tee
Server-verified attestation reports a trusted execution environment.
software_attested
A valid attestation explicitly reports software security.
web_key
Browser-generated key, or an explicitly labeled Android development fallback when hardware attestation is not verified.

The public device ID is the base32 SHA-256 fingerprint of the P-256 SubjectPublicKeyInfo. ProofLine does not use IMEI, serial number, MAC address or Android ID as provenance identity.

A fresh session key is bound to the device identity through a signature covering the server nonce, capture ID, policy, declared streams, start time and session public key.

Fragment chain

media_digest = SHA256(exact_fragment_bytes)

chain_digest = SHA256(JCS({
  protocol_version,
  capture_id,
  stream_id,
  sequence,
  previous_chain_digest,
  media_digest,
  byte_length,
  pts_start_us,
  pts_end_us,
  telemetry_root
}))

The gateway verifies the route identity, upload capability, session signature, independently computed media digest, chain predecessor, sequence, PTS policy, BMFF shape, codec, fragment size and quotas. It writes durable object storage before issuing a receipt.

First-frame wording: ProofLine can identify the first encoded frame in the app-signed chain. Android does not provide a universal trusted path from image sensor to application signature.

Durable server receipts

A server receipt binds:

  • Capture, stream and sequence
  • Independent media and chain digests
  • Predecessor and exact byte length
  • Server receipt time
  • Durable object key and object version
  • Server public key and ES256 signature

Identical retries return the original receipt. A conflicting duplicate is rejected and remains visible in structured logs and audit evidence.

A receipt means “these exact bytes were durably received by this server.” It does not mean “the sensor produced no later frame.”

Video and audio

The production target is ISO BMFF/CMAF with H.264/AVC and AAC-LC in two-second fragments. Hashing the exact fragment bytes binds every track present in that object. Reports also expose track-oriented roots so audio, video and telemetry results can be discussed separately.

The current Android client records independently playable, signed two-second MP4 assets through CameraX. The committed Media3/CMAF fixture validates the intended fragmented container path separately. This limitation is reported, not relabeled as live C2PA.

Microphone audio is captured once and linked as shared evidence when front and rear camera streams are present. Player mute state is presentation, not evidence.

Endings, gaps and recovery

CompletenessMeaning
complete_with_signed_endA valid device-signed end manifest covers every declared track, count and final digest.
complete_as_server_receivedThe report covers the highest contiguous prefix accepted before the resume window expired.
gaps_detectedCounts, predecessors, stream declarations or final digests do not reconcile.
pendingThe capture is still initializing, live, stalled or awaiting finalization.

End reasons are user_stop, duration_limit, permission_revoked, thermal_shutdown and app_error. A signature can show that the device key authorized the manifest; it cannot prove who pressed the button or whether they acted voluntarily.

Late valid fragments after interruption become recovery supplements. They never replace the original interruption assertion or prior receipts.

Receipt anchors and time

The worker builds deterministic Merkle roots across newly accepted receipts in 60-second batches and signs the leaf set. When configured, it sends the root to an RFC 3161 timestamp authority and preserves the raw response.

A server-signed Merkle root is a compact commitment, not an independent time witness. A TSA response becomes independent corroboration only after its signature, policy and certificate chain are validated. TSA failure remains a warning; already durable evidence is not rejected.

C2PA

The repository pins official c2patool 0.26.60 for a synthetic AVC/AAC CMAF fixture. Asset binding validates with trust checking disabled, and strict checking correctly rejects the untrusted development credential.

Current Android and PWA output does not receive a live C2PA or finalized-asset C2PA claim. Evidence reports state unsupported_for_current_capture_format and not_generated. Proprietary sidecars are never called C2PA-conformant.

Evidence bundle

The self-contained bundle includes canonical JSON, detached JSON/PDF signatures, report PDF, server public key, raw accepted fragments, fragment envelopes, receipts, telemetry batches, anchors, device end manifest, audit events, recovery supplements, C2PA status and any tombstone action.

Independent check: recompute fragment bytes, chain inputs, signatures, receipt-tree roots and report hashes from exported material. Do not treat the UI’s green state as proof by itself.
