Media-plane scenario coverage

Accepted

Valid progression

Signed session, initial fragment, identical duplicate retry, durable receipt, device-signed end and retained public report.

Recovered

Interrupted progression

Forced interruption, server-received-only finalization and a late valid recovery supplement without history rewrite.

Rejected

Integrity attacks

Forged signature, reordered sequence, conflicting bytes, mutated payload and wrong end signer.

Suppressed safely

Tombstone

Invalid admin signature rejected; valid offline signature hides media while preserving the report and audit evidence.

Android artifacts and reproducibility

Local artifacts are produced under artifacts/android/ and intentionally ignored by Git. The runtime payload matched across two clean release builds. Full APK/AAB bytes did not match because signature containers and R8’s build-time diagnostic metadata vary.

Trust boundary: the generated release APK/AAB uses an ephemeral development signing key. It is reproducibility evidence for the payload—not a production publisher identity.

Not verified here

  • StrongBox/TEE attestation chain, Google revocation status, verified boot/root of trust and production package-signature allowlisting.
  • Real-phone camera, microphone, GNSS, barometer, inertial timing, thermal shutdown, process death, storage pressure and concurrent cameras.
  • Execution of the Compose instrumentation test on an emulator or phone; the test APK compiled only.
  • Continuous Media3-authored CMAF from Android.
  • Final-asset C2PA for current capture output or an independently installed official validator separate from the authoring executable.
  • Server-generated preview sprites and hover/stylus scrubbing.
  • Production TSA, C2PA trust chain, weather adapters, KMS/HSM/PKCS#11 and an independent hostile-server witness.
  • VPS DNS/TLS/deployment, separate-host restore, public Sites access and anonymous production capture.

Physical-device acceptance matrix

Record device model, OS build, security patch, camera IDs, concurrent combinations, keystore security level, attestation result, sensor availability, 15/30/60-minute thermal behavior, offline/reconnect behavior and exported bundle hashes.

Before production readiness, test at least one StrongBox device, one TEE-only device and one device without concurrent-camera support. Emulator success is not a substitute.

Repeat the checks

./scripts/verify-local.ps1
./scripts/verify-local.ps1 -IncludeRust -IncludeContainers -IncludeAndroid -IncludeC2pa

The second command can take substantially longer and requires Rust 1.88, Docker, Android SDK/JDK and FFmpeg.
